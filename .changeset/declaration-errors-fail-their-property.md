A declaration error in `oracleProperty` now fails only its own property. Before, it failed the whole test file's load, so the file reported no tests and its other properties never ran. The property now registers a single test, `registration: <option>`, named by the option the error rejects: `owns`, `work`, `predict`, `histories` (an enumerated source's shape or data, `bases`, `drawnBases`, a required state with no constructed history, an undeclared state, or two tests of one name), `label` (a label that names `reach` or `determinism`), or `calibrations` (a calibration's history selector, a `probeHistories` binding, or a required difference that the empty difference holds). That test fails with the same error as before, the same message, and an `OracleDataError` for an enumerated history that is not data. The rest of the file runs and reports. The checks and their order are as strict as before, and the property runs none of its histories, campaigns, calibrations, or determinism tests until the declaration is fixed. Like a `membership:` test, it runs in every run and in a path replay of its own property. Two errors still fail the file: an id that is not in `configureOracles`' registry, and a path replay whose `UNIT` the property cannot run. In `oracle-gaps`, the test is a failing law: it blocks only the mutants that no passing owner test reaches.
