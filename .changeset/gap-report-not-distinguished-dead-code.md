The `oracle-gaps` directive for a `not-distinguished` gap of a dropped property (`field-drop`), an `undefined` call value (`value-undefined`), or an `undefined` return (`return-undefined`) now names the step for dead code after the history to add: where no legal history tells the mutant from the original, the code is dead, to be removed, keeping any effect it has, and where it was written only so that a type checks, the type of what is read is declared instead. Before, the directive pointed only at adding a history, and no history can kill a mutant of a value nothing reads, such as `start: 0` on an object typed wider than what is read, or `return {}` where the result is spread. The design skill says the same.
