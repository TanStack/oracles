Add ESLint rules for oracle tests: no disabled oracles, no unit tests in oracle files, pure models, replayable seeds, and the production probe form. `oracle/no-unit-test` holds an oracle file to registering its tests only through `oracleProperty`. It reports every other test registration as a unit test, and a helper that registers its caller's body. It also reports an `oracleProperty` call without an inline `check`, and an imported helper that registers tests of its own. `oracle/no-unit-test`, `oracle/no-disabled`, and `oracle/oracle-property-only` share one account of a test function: `it`, `test`, `describe`, `suite`, or `bench` imported from any package or subpath alias, or a fixture of one. The rules cannot read a package, so they fail closed there. They follow imports, aliases, namespace members, variables and their assignments, destructurings, casts, the branches of a conditional or logical expression, tagged-template `.each`, and the exports of relative test modules. A binding to anything else, and a member that is no registration such as `test.step`, is no test function, whatever its name. The README lists the forms that the rules do not recognize: a test function passed as a parameter, one that a package exports under another name, a computed member that is not a string literal, and a modifier call that another module exports. A fixed history, case, calibration, or reach check goes in the property's histories, calibrations, and declared states; any other test goes in an ordinary test file. `settings.oracles` sets the environment prefix and the modules that count as implementation and replay-witness modules.

Add the `oracle/oracle-property-only` rule, enabled in `configs.recommended`. In an oracle file it reports a raw property campaign (`fc.assert`, `fc.check`, or a `.prop` registration, through `fast-check` or `@fast-check/vitest`) and an import of `createOracleReach` or `runOracleCampaign`, so a generated-history law runs through `oracleProperty` and its constructed histories. Framework implementation modules are exempt. A non-array `implementationModules` or `replayWitnessModules` is reported at line 1 and read as empty. The rule never throws.

Add the `oracle/no-oracle-disable` rule, enabled in `configs.recommended` and `configs.production`. It reports every ESLint directive that would silence an `oracle/*` rule: a rule list that names one (bare, single-quoted, or double-quoted), a directive with no rule list, and an inline config comment that names one. Oracle rules cannot be disabled inline. A report sits on the directive's line; a directive that names this rule or has no list, or that an earlier block directive covers, is reported at line 1, column 0. Residuals the rule cannot close: a directive on line 1 that names this rule or has no list, and a production config comment that turns this rule off.

The `recommended` config sets `linterOptions.noInlineConfig` on oracle files. ESLint ignores every directive in those files, for every rule, not only the oracle rules. A directive for another rule in an oracle file has no effect, so a project that relied on one must move the suppression or fix the code. The production config's probe-form rule covers `packages/*/src` and a single-package `src` directory.
