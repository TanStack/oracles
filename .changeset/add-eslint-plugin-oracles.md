Add ESLint rules for oracle tests: no disabled oracles, no unit tests in oracle files, pure models, replayable seeds, and the production probe form. `settings.oracles` sets the environment prefix and the modules that count as implementation and replay-witness modules.

Add the `oracle/oracle-property-only` rule, enabled in `configs.recommended`. In an oracle file it reports a raw property campaign (`fc.assert`, `fc.check`, or a `.prop` registration, through `fast-check` or `@fast-check/vitest`) and an import of `createOracleReach` or `runOracleCampaign`, so a generated-history law runs through `oracleProperty` and its constructed histories. Framework implementation modules are exempt. `settings.oracles.legacyCampaigns` lists `{ file, reason }` entries for files that still migrate. An entry without a reason, and an entry with no legacy use left, are reported as stale or unexempted. A malformed entry, a `legacyCampaigns` value that is not an array, or an entry that names a file outside the oracle-file glob or a framework implementation module is reported at line 1 and exempts nothing; the rule never throws. An entry for a deleted or renamed file is not reported. The rule sees one file at a time, so it cannot stop a baseline from growing; a project enforces shrink-only in its own diff check.

Add the `oracle/no-oracle-disable` rule, enabled in `configs.recommended` and `configs.production`. It reports an ESLint disable directive that names an `oracle/*` rule, in the line, next-line, and block forms, with or without a description, because oracle rules cannot be disabled inline. A blanket `eslint-disable` with no rule list is not seen. Also, `configs.recommended` sets `linterOptions.noInlineConfig`, so a directive in an oracle file has no effect (ESLint warns). The production config's probe-form rule covers both `packages/*/src` and a single-package `src`.
