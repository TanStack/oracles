The `oracle-gaps` report gives each gap a class and one directive with a concrete next step. A message never offers an exit such as an equivalent mutant or a maintainer approval. Survivors are `not-judged`, `indeterminate`, `dead-code`, `branch-never-taken`, `not-infected`, or `not-observed`. A `crashed` gap names the error that production threw, and tells the author to record it as an observation and state the law. Standard output is short: the totals, one legend line for each class, gaps grouped by function, unowned warnings counted for each function, and the paths of `summary.md` and `results.json`. The full report is in `summary.md`. The CLI also streams its progress: the baseline result first, then one line for each gap when the CLI judges it, then the summary.
