The `oracle-gaps` directive for a `not-observed` gap now names a third and last case: where every path overwrites the changed value before anything reads it, such as an initializer written only for the type checker, the code is dead, but only with evidence: a law that decides the value exactly owns every public entry point that reaches the code, and the gap runs before and after its removal keep every kill by mutant key. With that evidence the value is to be removed, keeping any effect it has. Before, the directive pointed only at the oracle (observe the value, or add a history where the mutated code computes something different), and neither step can kill a mutant of a value that nothing ever reads. The design skill says the same.
